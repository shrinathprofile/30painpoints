# Learnings

The compounding knowledge base of the 30-day series. Every day's retro feeds one insight into exactly one file here. If a learning doesn't change tomorrow's behavior, it doesn't get an entry.

| File | What goes in |
|------|--------------|
| [`TECHNICAL.md`](TECHNICAL.md) | Language/API quirks, patterns worth reusing, debugging moves, stack-specific gotchas, `ponytail` wins (stdlib/native beats) |
| [`PRODUCT.md`](PRODUCT.md) | Problem-validation signals, scope-cut decisions that proved right/wrong, what users actually wanted vs what was built, Reddit-as-research method |
| [`BUSINESS.md`](BUSINESS.md) | Content/audience learnings: what hooks work, post mechanics, engagement patterns, positioning, recruiter/inbound signals, distribution tactics |

## Rules

1. One entry per day per file, max. Forced brevity forces extraction.
2. Every entry is dated and tagged with the day number: `### D01 — title`.
3. An entry must be *actionable tomorrow* — a rule, a pattern, or a warning. Observations without consequences get cut.
4. Contradictions are allowed: new entries may overturn old ones, but the old entry gets a `↩︎ overturned by D17` note rather than deletion. The trail is the point.
